# DocMend enhancement modules

## 1. Action and release integration (0.2.0)
Validated fail-on values and single-line output paths before analysis. Offline operation, fork restrictions and explicit publishing remain. SARIF output complements JSON, Markdown and patches. Consumers use the real repository with a version or audited commit.

## 2. Source understanding
Existing Python AST, TOML and fence-aware Markdown parsers. Next: language adapters with source-span contracts and independent fixtures. Unsupported languages must remain explicit coverage gaps.

## 3. Evidence and diagnosis
Existing static contract comparison and optional real embeddings/model review. Next: benchmark on independently annotated repository changes, including negatives and abstention. Constructed fixture results are not field accuracy.

## 4. Repair safety
Existing recomputation, hashes, structural checks, locks and rollback. Next: crash-injection tests and independent multi-file recovery verification. Model output remains a draft.

## 5. Review and interoperability (0.2.0)
New SARIF 2.1.0 artifacts: stale errors, unresolved review warnings, stable section fingerprints and analysis-limit notifications. No invented line locations or automatic fix declarations. Upload requires a separately authorized code-scanning step. Dashboard remains report-import only.

## 6. GitHub collaboration
Existing opt-in same-repository draft repair PRs. Next: explicit lifecycle policies, concurrency/rerun stress tests and GitHub App validation. No automatic merge.

## 7. Operations and evaluation
Existing bounded provider calls and Python/container CI. Next: live provider compatibility with authorized credentials, measured runtime budgets and human-reviewed evaluation. No production SLA claimed.

## Release gates
Run full tests, isolated demo and remote Python/container CI. Publish a prerelease while live-provider and real-world benchmark gates remain open. Marketplace publication additionally needs owner acceptance of the Developer Agreement and the Marketplace checkbox in GitHub's release UI. A GitHub release alone does not create a Marketplace listing.
